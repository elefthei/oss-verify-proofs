# Proving or refuting a statement

A proof is a directory `proofs/<project>/<harness>/<statement>/` holding a
`Proof.v`, any helper `.v` files beside it, and a `proof.yaml`; `oft generate`
adds its `dune` file. Files that several proofs of a harness share go in
`proofs/<project>/<harness>/lib/`. `Proof.v` ends in a theorem named after the
statement:

    From OssFuzzTheorems.zlib.checksum_fuzzer Require Import Statements.

    Theorem plain_halts_holds : Statements.plain_halts.
    Proof. (* ... *) Qed.

A bound proof names its bound, `Theorem asan_disagrees_at_most_holds :
Statements.asan_disagrees_at_most (1 # 1000).`, and records it in `proof.yaml`
as `bound: 1/1000`. A refutation is a `Refutation.v` ending in
`Theorem plain_halts_refuted : ~ Statements.plain_halts.`, with `refutes:`
instead of `proves:`.

`proof.yaml` ([schema](../tools/oft/schemas/proof.yaml)) tells the checker which
statement the proof is of, and pins it to that statement's published
fingerprint:

    schema: oss-fuzz-theorems/proof/1
    proves: zlib/checksum_fuzzer/plain_halts
    fingerprint: <the statement's fingerprint in index/statements.tsv>

The fingerprint must be the statement's current one, so a proof is always of the
statement as published. `check:` (wall time and peak memory), when present, is
written by CI or a maintainer, never by the author. The file names no author.

## What a proof may use

Only Rocq's own libraries (Corelib, Stdlib, Ltac2), the library of this
repository, the LPS core library (`LinuxProcessSemantics`) and the libraries it
builds on (stdpp, Flocq, rocq-read-file). A proof
may not declare an `Axiom` or `Parameter`, end in `Admitted`, load a plugin,
touch files or switch a checker off; `oft lint` refuses those on sight (its
`proofs` rule), and what the wrapper's `Print Assumptions` lists, every entry
checked against [toolchain/allowed-axioms.txt](../toolchain/allowed-axioms.txt),
is the authority. Nor may a proof set a wall-clock limit, which can fail a
check on a loaded machine: no `Set Default Timeout`, no `Timeout` command and no
`timeout` tactical whose expiry can fail its sentence (one under `try` or
`repeat`, or in a `first` or `solve` arm that is not the last, is fine). The
same rule refuses those.

## Where to start

- [tests/](../tests/) has toy binaries of a few instructions (generated by
  `tests/toy/make_elf.py`), their statements, finished proofs of the halts,
  halts-may-fail and agreement shapes, one refutation, and proofs that must be
  refused.
- The smallest published plain images are about 42 KB
  ([index/binaries.tsv](../index/binaries.tsv) lists every size). Statements about
  them still need the start-up code of musl and the driver to be reasoned about.
  The published proofs do this for their own binaries, in their `lib/`; no
  shared library for it is published yet.
- A refutation is often one concrete execution, and a good first result. So is a
  counterexample to a halts statement: a failing input for the real binary,
  which goes in `counterexamples/<project>/<harness>/<statement>/` with
  `input.bin`, a nearby `control.bin` that exits with a status the statement
  allows, and `expect.yaml` ([schema](../tools/oft/schemas/counterexample.yaml)).

A counterexample that shows a memory-safety bug in a library goes to that
library first ([SECURITY.md](../SECURITY.md)). Checking a proof needs LPS and
the checker image that [release.yaml](../release.yaml) names
([checking.md](checking.md)).

## Checking a proof locally

    ./oft fetch zlib
    python3 -m pip install --require-hashes --target "$HOME/oft-pydeps" -r tools/oft/requirements.txt
    docker run --rm --network none -u "$(id -u):$(id -g)" -e HOME=/tmp -e PYTHONPATH=/pydeps \
      -v "$HOME/oft-pydeps:/pydeps:ro" -v "$PWD:/work" -w /work <checker image of release.yaml> \
      ./oft check zlib/checksum_fuzzer --parts statements,proofs

`oft check` builds the images and statements, checks every proof of the harness
(counterexamples are checked in the runner image, with `--parts counterexamples`)
through a wrapper that it writes itself, and checks every assumption the wrapper
prints against the allowlist ([checking.md](checking.md)). `--rocqchk` adds an
independent re-check with `rocqchk`, which can take hours for one proof.

## Junco liveness workflow

[`liveness.yml`](../liveness.yml) and [`liveness.ts`](../liveness.ts) assign one
GPT-6.1-sol verifier to each of the README table's 25 libraries and to zlib,
which the README names in its statement example. Each verifier inventories all
of that library's harnesses and available builds, not only its existing proofs.
An Opus 5.5 proof reviewer/minimizer sends corrections back to the same
verifiers; review rounds have no fixed cap. A separate Counter-example reviewer
checks the infinite-execution witnesses and source locations before publication.

Requires Bun, the public `junco-agency` and `@earendil-works/pi-*` packages,
Junco's working native tool collection, and a saved Pi GitHub Copilot login
with `gpt-6.1-sol` and `claude-opus-5.5` access. CTrees, TICL and the Linux
process semantics, including its `rocq-linux-process-semantics-liveness`
package, must be installed from `~/git/ctrees`, `~/git/ticl` and
`~/git/rocq-linux-process-semantics` into the opam switch `lps-ctree`, and every
library's published binaries must be present (`./oft fetch LIB`; the workflow
never downloads). There is no model fallback.

    bun run liveness.ts
    bun run liveness.check.ts            # credential-free review/CSV/preflight boundary check

The shared liveness definitions and their real-image checks live in that
package (`LinuxProcessSemantics.Liveness.AF` and `.Checks`), not here. Before
any model or agent is acquired, `liveness.ts` runs the shared gate
[`liveness/check.sh`](../liveness/check.sh) in a fresh
`liveness/preflight-*` directory: it checks every library's published ELFs
against their SHA-256s, loads the installed stack in one closure (recording the
assumptions of its theorems and the hashes of every library it resolved), and
builds each published harness's `Images.vo`. To run the gate alone:

    env -u COQPATH -u ROCQPATH opam exec --switch=lps-ctree -- bash liveness/check.sh EMPTY_DIR [LIBRARY...]

If these packages are already installed in a sibling Junco checkout rather
than resolvable from this repository, prefix either command with
`NODE_PATH="$HOME/git:$HOME/git/junco-agency/node_modules"`.

Proof attempts and checker evidence go under `liveness/<library>/`; the final
report is `liveness/report.md`. Confirmed counter-examples produce
`liveness/counterexamples.csv` with columns `bugId,file,function,line number,counter-example of liveness`.
One bugId may occupy multiple source-location rows. No confirmed counter-example
means no CSV, not a proof of liveness. Existing report/CSV files are not overwritten.
A failed preflight or other missing prerequisite ends the workflow with a
BLOCKED report and nonzero exit; SIGINT/SIGTERM or an operational error writes a
CANCELLED/FAILED INCOMPLETE report with each node's status, never a verdict.

This development uses the local CTrees/TICL/CSL frameworks separately from the
release checker. It does not extend `oft`'s permitted dependencies or make a
proof a release result. Agreement, finite trace equivalence, timeouts and
bounded execution do not prove non-spinning; each claimed result needs its
divergence-sensitive whole-program bridge and actual kernel checks.
